# Permissions

The plugin's commands follow Tauri's capability system. A webview can call a
command only when one of its capabilities grants the permission. All
identifiers start with `overwolf:`. The files are in
`crates/tauri-plugin-overwolf/permissions/`; the generated list of every
identifier is `permissions/autogenerated/reference.md`.

## Sets

| Set | Grants | Grant it when |
|---|---|---|
| `overwolf:default` | `<owadview>` (`adview_mount`, `adview_update`, `adview_unmount`, `adview_command`), `get_info`, `set_window_name`, `is_cmp_required`, `open_ad_privacy_settings_window`, `open_cmp_window`, `disable_anonymous_analytics`, `disable_ads_optimization`, `disable_ads_fpd` | the webview shows ads or the privacy settings entry |
| `overwolf:machine-id` | `get_machine_ids` | you need the machine ids every Overwolf app shares |
| `overwolf:email-hashes` | `generate_user_email_hashes`, `set_user_email_hashes`, `clear_user_email_hashes` | you send the user's email hashes (personal data) |
| `overwolf:analytics` | `set_external_payment_user_id`, `set_analytics_user_enabled`, `set_anonymous_analytics_preference` | you report a payment user id, or store the user's analytics choice |
| `overwolf:updater` | `updater_check`, `updater_download`, `updater_install`, `updater_download_and_install` | the webview runs the Windows updater |

`overwolf:default` contains the three switches that reduce what is sent, so
a page with only the default set can honour a user's privacy choice for the
current launch.

Each command also has its own `overwolf:allow-<command>` and
`overwolf:deny-<command>` permission, with `_` written as `-` (for example
`overwolf:allow-get-info`).

## Never grant

| Set | What it is |
|---|---|
| `overwolf:adview-guest` | the ad pages' one command (`adview_event`) |
| `overwolf:cmp-window` | the consent page's one command (`cmp_event`) |

The plugin adds both itself, at run time, bound to its own webview labels
(`owad-*`, `ow-cmp*`) and to Overwolf's exact page addresses. An app
capability that grants them gives nothing useful and widens access.

## Example

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Main webview: core APIs and Overwolf ads, consent and identity",
  "webviews": ["main"],
  "permissions": ["core:default", "overwolf:default", "overwolf:analytics"]
}
```

## Select webviews, not windows

Name the webviews in a capability (`"webviews": ["main"]`), never the
windows. An ad is a child webview inside your window. A capability that
names the window would also match the ad page, and Overwolf's ad page would
get your app's permissions. The build step warns about every `windows`
selector while the `ads` feature is on; `ow-tauri doctor` does too.

Never add a `remote.urls` entry that covers `*.overwolf.com` or every origin
(`https://*`). The build step fails on it.

## The caller check

Besides the capability, every app command checks the caller:

- the webview is not one of the plugin's own (`owad-*`, `ow-cmp*`);
- the page is a local app page: Tauri's app origin (`tauri://localhost`,
  `http://tauri.localhost`, `https://tauri.localhost`), the `devUrl` origin
  in a debug build, or an origin in `ads.allowedEmbedderOrigins`;
Otherwise the call fails with `forbidden`. For `adview_update`,
`adview_unmount` and `adview_command` the element must also have been
mounted by the same webview; another webview's element is `not-found`.
